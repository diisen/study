# アカウント・学習データ同期の設計メモ（Cloudflare Workers + D1 ハイブリッド方式）

## 1. 背景と決定事項（2026-11-02）

- **現在の実装フェーズ**:
  - アプリ本体の機能・UIの作り込みを優先するため、現時点ではブラウザ標準の **`localStorage`**（キー: `ncea_vocab_quest_v1` など）のみで動作させている。
- **将来導入する方式（決定済み方針）**:
  - **「ローカル即時保存（`localStorage`）＋ Cloudflare Workers & D1 へのバックグラウンド自動同期」のハイブリッド方式** を採用する。

---

## 2. なぜこの方式を選んだか（検討の経緯）

1. **引き継ぎコード（手動コピー＆ペースト）方式を不採用とした理由**:
   - PCやスマホの突然の故障・水没・ブラウザデータ消失時に、事前にコードを発行していないとデータを救出できないため。
2. **Googleアカウント連携（OAuth）を不採用とした理由**:
   - 生徒本人が「他人が作った個人アプリに自分のGoogleアカウントを連携したくない」というセキュリティ・プライバシー上の懸念があるため。
   - また、メールアドレスなどの個人情報も一切入力・保持しない設計が望ましいため。
3. **Supabase ではなく Cloudflare Workers + D1 を選んだ理由**:
   - Supabase の無料枠には「7日間アクセスがないとプロジェクトが自動停止（Pause）される」仕様があり、定期試験の合間など1〜2週間アプリを開かない期間があるとログイン・同期ができなくなるリスクがある。
   - **Cloudflare Workers + D1** は無料枠（1日10万リクエスト / 5GB）が非常に広く、**長期間放置しても自動停止（スリープ）しない**ため、個人学習アプリの長期運用に最適。

---

## 3. 実装時のアーキテクチャ仕様（メモ）

### ① 認証（メールアドレス不要の「ユーザーID ＋ パスワード」方式）
- ユーザーは任意の **ユーザーID（例: `kiwi_y12`）** と **パスワード** の2つだけでアカウントを作成・ログインできる（メールアドレス不要）。
- パスワードは Worker 側で Web Crypto API（`PBKDF2` または `scrypt` + ソルト）を用いてハッシュ化して D1 の `users` テーブルへ保存する。
- ログイン成功時は署名付きトークン（JWT またはランダムセッショントークン）を発行し、クライアントの `localStorage` に保存する。

### ② ハイブリッド自動保存（Offline-First + Auto Cloud Backup）
1. **即時ローカル保存（0ms）**:
   - クイズ回答・カード仕分け・XP獲得のたびに、まず `localStorage` を即座に更新する（通信待ちによる画面の引っかかりをゼロにし、オフラインや移動中でも快適にする）。
2. **デバウンス自動クラウド同期**:
   - ログイン状態であれば、変更発生から数秒後（Debounce 2〜3秒）にバックグラウンドで `POST /api/sync` を呼び出し、D1 上の学習データ JSON を自動更新する。
3. **スマートマージ（端末切り替え・後からのアカウント登録対応）**:
   - ログイン前にゲスト状態で進めていたデータがある場合や、スマホとPCの両方で学習した場合でもデータが巻き戻らないよう、同期時に以下をマージする：
     - `xp`, `bestCombo`, `bestBlitzScore`, `bestSurvivalScore`, `totalAnswered`: 大きい方の値（`Math.max`）を採用
     - `mastery`（各単語の習熟度 `0 | 1 | 2`）: 単語ごとに高い方の習熟度または最終更新時刻が新しい方を採用

### ③ D1 データベース最小スキーマ案
```sql
CREATE TABLE IF NOT EXISTS users (
  user_id TEXT PRIMARY KEY,
  password_hash TEXT NOT NULL,
  salt TEXT NOT NULL,
  study_state_json TEXT NOT NULL DEFAULT '{}',
  updated_at TEXT NOT NULL
);
```
- `study_state_json` に `vocab` だけでなく、将来的に `physics`（ハイスコア等）や `psychology`（A3プランニングシートの下書き等）のデータもまとめて格納できるようにすると、ポータル全体で1つのIDを共有できる。
